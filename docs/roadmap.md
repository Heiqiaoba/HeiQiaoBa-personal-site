# 黑巧笔记 · 功能规划

> 状态：规划稿，尚未实现。实现顺序建议按下面「阶段」推进。

## 一、现状

- 前端：React SPA，仅首页（数字花园风格）、登录注册、404、语言切换（zh/en）
- 后端：Fastify + Better Auth + Drizzle，只有 4 张认证表（user/session/account/verification）
- 站点是「公开访问 + 私有管理」结构：访客只读，作者登录后进管理后台写内容

## 二、内容模块（博客能干什么）

### 1. 笔记（Notes）—— 主力内容
日志式短文，对应数字花园/工作日志的定位。
- 字段：标题、正文（Markdown）、摘要（可自动生成）、标签（多对多）、状态（草稿/已发布）、发布时间、更新时间、slug（URL 短名）
- 页面：列表（按时间倒序，标签筛选）、详情（`/notes/:slug`）、归档（按年月）
- 特点：更新压力小，一条可以只有几百字

### 2. 项目（Projects）
展示做过的东西，静态数据即可（硬编码在前端），不必进数据库。
- 字段：名称、描述、技术栈标签、链接（GitHub/演示）、截图
- 页面：`/projects` 卡片列表

### 3. 关于（About）
一页静态介绍，中英文各一份。放在前端常量里即可。

### 4. 标签与搜索（后续）
- 标签云 / 按标签过滤笔记
- 前端本地搜索（pagefind 或简单客户端过滤），日积月累文章多了再做

### 5. RSS / Atom（后续）
自动生成 `/feed.xml`，方便订阅。后端加一个路由即可。

### 6. 访客留言（可选，谨慎）
- 方案 A：不开放评论，只留邮箱/GitHub 链接（最省心，推荐起步）
- 方案 B：接入第三方评论系统（Giscus，基于 GitHub Discussions，免数据库、免审核）
- 方案 C：自建评论表 + 审核机制（工作量最大，后期再说）

## 三、后台管理（发布文章）

### 路由结构（2026-11-26 更新）
- `/write` —— 写作台首页（笔记列表，含草稿/已发布状态、编辑/删除入口；需登录 + admin 角色）
- `/write/new` —— 新建笔记
- `/write/:id` —— 编辑笔记
- 入口：导航栏「写作台」（登录后可见）、首页「+ 写笔记」、文章详情「编辑这篇」
- Markdown 编辑器：从轻量 textarea + 预览，到 MDXEditor / Milkdown 逐步升级
- Markdown 编辑器：从轻量 textarea + 预览，到 MDXEditor / Milkdown 逐步升级

### 后端 API（`/api/v1/notes`）
| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/notes` | 公开 | 已发布笔记列表（分页、标签筛选） |
| GET | `/notes/:slug` | 公开* | 笔记详情（草稿仅 admin 可见） |
| GET | `/admin/notes` | admin | 全部笔记（含草稿） |
| POST | `/admin/notes` | admin | 新建 |
| PATCH | `/admin/notes/:id` | admin | 更新 |
| DELETE | `/admin/notes/:id` | admin | 删除（建议软删除） |

### 数据表
- `notes`：id、slug(唯一)、title、summary、content(markdown)、status(draft/published)、published_at、created_at、updated_at、deleted_at(软删除)
- `tags`：id、name(唯一)
- `note_tags`：关联表（多对多）
- 中文 slug 处理：用拼音或直接用 id 短码，避免 URL 编码问题

## 四、权限设计

### 角色模型
沿用 Better Auth 的 admin 插件，角色两种：
- `user` —— 访客注册后默认角色（但本站**不开放公开注册**，见下）
- `admin` —— 站主，唯一能进后台、发布/编辑/删除内容的人

### 关键决策：关闭公开注册
个人站只需要一个作者账号。两种做法：
- **推荐**：关闭 signUp 入口（前端隐藏注册、后端禁用或限制注册），作者账号由你在数据库/脚本里创建
- 或保留注册但所有新账号都是 `user`，`user` 无任何管理权限

### 权限校验在哪做（重要）
1. **后端是唯一安全边界**：所有 `/api/v1/admin/*` 路由挂 `requireAdmin` 钩子，前端守卫只是体验层
2. 前端 `AdminGuard`（模板里有现成的）控制后台路由可见性，未登录跳登录、非 admin 显示无权限
3. 公开接口只返回 `status=published` 的数据；草稿在后端查询层就过滤掉，不依赖前端隐藏

### 站主账号初始化
- 用脚本 `pnpm set-role <email> admin`（模板已带）把你的账号提升为 admin
- 生产环境把你的 user id 配到 `ADMIN_USER_IDS` 环境变量，双保险

## 五、访客问题

### 访客能做什么
- 浏览首页、笔记列表/详情、项目、关于
- 中英文切换（语言存 localStorage，不影响服务端）
- 看到登录入口（可保留，但注册建议关闭）

### 访客不能做什么
- 看不到草稿、看不到管理后台
- 不能调用任何管理 API（后端强制校验）
- 不能写数据（本站无评论表时）

### 隐私保护
- 访问日志/埋点：保留模板的匿名埋点，但**不采集 query 参数**（模板已做到），可在 `.env` 设 `VITE_TELEMETRY=false` 关闭
- 不采集访客 IP 明细、不存 Cookie 以外的身份信息（Better Auth 会话 Cookie 除外）

### 部署后访客量大了怎么办（后期）
- 笔记详情加 CDN 缓存 / 静态化（这是 SPA 的 SEO 短板，届时考虑预渲染或迁 SSG）
- 数据库连接池上限 `DB_POOL_MAX` 按流量调整
